# Kaiser 个人品牌网站设计

**设计状态：** 已在 2026-09-10 确认，进入实现计划阶段  
**主品牌：** Kaiser / 于越 / Yue Yu  
**主域名目标：** `kaiseriii.me`；注册时若状态变化，使用 `yuyue.me` 作为备用

## 目标

1. 建立一个能同时承担求职简历、留学展示、个人品牌和项目作品集的网站。
2. 网站的公开页面、项目演示和本地知识库服务全部运行在用户的 Windows 电脑上。
3. 使用 GitHub 进行源码管理、版本追踪、CI 检查和后续协作；使用 GitHub 学生权益获取域名与开发资源。
4. 提供 `hello@kaiseriii.me` 作为公开联系地址，并将来信转发到用户现有邮箱；本机不承担 SMTP 发信。
5. 让网站有明确的高技术力和华丽视觉识别，同时保持手机端可读、加载可控和核心内容可访问。

## 非目标

- v1 不把个人知识库的原始文档、聊天记录、邮件、家庭信息、学号、生日、成绩或内部接口暴露到公网。
- v1 不在本机搭建完整 SMTP 邮件服务器，不承担垃圾邮件信誉、反向 DNS 和运营商端口放行问题。
- v1 不实时把私有知识库作为公开聊天机器人；公开页面只使用人工审核后的脱敏资料快照。
- v1 不依赖大型 3D 引擎、持续运行的 WebGL 场景或外部图片 API。

## 用户体验与信息架构

网站采用单页章节式叙事，附带可选的项目详情页：

- `01 / PROFILE`：Kaiser / 于越的个人定位、专业方向和主要行动按钮。
- `02 / JOURNEY`：教育、实习、学生工作、竞赛和项目节点的时间线；只呈现已核验或明确标注状态的内容。
- `03 / BUILDS`：精选技术项目，包括个人知识库、设备检测工具、工程数据分析、Godot 游戏或课程系统；每张卡片包含技术栈、角色、状态和链接。
- `04 / SIGNALS`：GitHub、可公开的成果、证书和技能信号；不把 GPA、排名或内部投稿状态作为默认公开信息。
- `05 / CONTACT`：域名邮箱、GitHub 和其他经用户确认的公开链接，带一键复制邮箱功能。

初始公开画像采用安全子集：

- 姓名与英文署名：于越 / Yue Yu。
- 教育方向：东北林业大学工程管理，辅修计算机科学与技术。
- 兴趣方向：软件开发、人工智能、工程数据分析、本地优先工具和可复现工作流。
- GitHub：`KaiserIIII`。
- 项目：个人 Agent 知识库、QLDeviceCheck 设备检测工具、Construction Cost Analyzer、Godot 卡牌项目、无人机巡检课程项目。

正式上线前，所有“中等置信度”经历和成果仍需在本地预览页逐项确认；知识库中标记为 `private` 的内容不会进入公开资料文件。

## 视觉设计

采用用户选定的 C 方案“电影感数据叙事”：

- 高对比编辑式排版、大标题、章节编号、时间线和数据标签。
- 黑曜石/深靛蓝底色，使用蓝紫光晕和少量洋红作为强调色。
- 首屏像技术项目发布页，正文像一份精心编辑的数字档案。
- 背景使用 CSS/SVG 网格、扫描线、光晕和轻量粒子效果；尊重 `prefers-reduced-motion`。
- 项目区使用具有层次感的卡片和状态标记，但不让装饰遮挡项目描述。
- 默认深色模式，提供浅色模式和中英文切换。

交互包括章节导航、滚动进度、项目筛选、项目详情入口、简历下载、一键复制邮箱和键盘可操作的移动端菜单。没有 JavaScript 时，主要文字、链接和项目列表仍然可读。

## 技术架构

### 公开网站

- Astro + TypeScript 生成静态 HTML/CSS/JS。
- `src/content/` 保存项目 Markdown 和经过审核的公开个人资料。
- 组件按职责拆分为布局、首屏、时间线、项目网格、信号区、联系区和交互增强模块。
- 构建产物为 `dist/`，由本机 Caddy 直接提供静态文件。
- GitHub Actions 执行格式检查、类型检查、构建和链接检查；生产发布仍由本机部署脚本完成。

### 本机服务

```text
Cloudflare Tunnel
        │
        ▼
Caddy :443
   ├── kaiseriii.me          → 个人网站 dist/
   ├── lab.kaiseriii.me      → 项目演示入口
   └── 本机/受保护入口       → 知识库服务
                                │
                                └── LangBot/RAG：仅本机或明确认证后访问
```

- Caddy 负责统一入口、静态文件、反向代理和访问日志。
- Cloudflare Tunnel 使用出站连接，不要求家庭路由器开放入站端口。
- 个人知识库默认绑定本机回环地址或局域网，不创建公开匿名路由。
- 网站与知识库分进程、分目录、分配置；知识库的 SQLite、Chroma、上传文件和 API Key 不进入网站仓库。
- 本机重启后由一个可重复运行的启动脚本恢复 Caddy、网站预览、项目演示和知识库进程；服务不可用时，网站静态页面仍能独立打开。

### 资料流

```text
E:\\humanknow\\me（私有知识库）
              │ 人工审核的脱敏导出
              ▼
网站仓库 src/content/profile.public.md
              │
              ▼
Astro build → dist → Caddy → Cloudflare Tunnel → 公网域名
```

网站不在每次请求时查询个人知识库，避免私有内容越权、延迟和知识库故障影响主页。

## 隐私与安全边界

- 公共资料文件只允许出现公开身份、专业方向、已审核项目、已审核成果和经确认的外链。
- 禁止提交 `.env`、API Key、知识库数据库、Chroma 索引、上传文档、聊天导出和个人原始资料。
- 知识库管理接口不通过公开主页代理；需要远程管理时，先加身份认证和最小权限。
- Caddy 和 Tunnel 只公开网站与明确批准的演示路由；未知路径默认拒绝。
- 部署前扫描仓库和构建产物中的凭据、学号、邮箱原文、住址和私有文件名。
- 公开网站的内容变更属于对外发布，执行前先在本机预览并由用户确认。

## 验收标准

1. 在本机可通过一个命令启动网站、Caddy 和所需演示服务，且重启后可重复恢复。
2. 个人主页在桌面端和窄屏移动端无横向溢出，章节、项目和联系入口完整可用。
3. 电影感科技视觉明显，但关闭动画后内容层级和可读性不丢失。
4. 中英文切换、浅色模式、项目筛选、简历下载和复制邮箱在浏览器中可操作。
5. 私有知识库数据和密钥不会出现在 Git 状态、构建产物、公开域名或公开日志中。
6. Caddy 只代理已定义的路由；知识库匿名公网访问被拒绝。
7. DNS、Tunnel、HTTPS 和邮箱转发逐项验证；域名注册和任何最终外部提交在用户确认后执行。
8. 网站仓库具备 CI 检查，构建失败时不替换本机当前可用版本。

## 风险与应对

| 风险 | 应对 |
|---|---|
| 电脑睡眠、关机或网络波动 | 网站提供服务状态页；建立本机启动脚本；未来可用学生云额度迁移 |
| 家庭网络无公网 IP 或端口受限 | 使用 Cloudflare Tunnel 的出站连接，不依赖端口转发 |
| 域名在实际注册时被占用 | 先尝试 `kaiseriii.me`，再切换 `yuyue.me` |
| 知识库误暴露 | 不公开 RAG 路由，默认只绑定本机，必要时增加 Access 认证 |
| 公开资料包含不准确或过期内容 | 内容采用人工审核快照，给动态经历保留状态和日期 |
| 邮箱转发只能收信 | v1 仅承诺稳定收信；发信能力单独评估和配置 |
